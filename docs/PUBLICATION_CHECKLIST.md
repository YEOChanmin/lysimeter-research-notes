# Checklist for Future Publication Updates

Use this checklist when adding source, data, figures or a new documentation edition. A box should be marked only when the relevant review or authorization has actually occurred. This checklist does not certify the initial edition or authorize operational actions.

## Selection and provenance

- [ ] Confirm repository ownership, visibility and the scope of the update.
- [ ] Select individual files instead of copying the research folder or its Git directory.
- [ ] Reconcile working files, sealed candidates and deployed versions.
- [ ] Verify dependencies and reproduction instructions for any executable source.
- [ ] Exclude generated output, private tools and obsolete variants.

## Private information

- [ ] Review all selected text, examples, images and binaries for credentials and private identifiers.
- [ ] Review any Git history that will be included separately from current files.
- [ ] Remember that ignore rules do not remove previously tracked content or historical secrets.
- [ ] If a secret is found, keep it out of public reports and arrange private remediation; file deletion alone is insufficient.

Do not post sensitive security details in a public issue. Use GitHub's private vulnerability-reporting channel if the repository has one enabled. No dedicated private reporting channel is established by this documentation edition.

## Research and rights

- [ ] Confirm the permitted scope for raw data, photographs, backups and incident records.
- [ ] Confirm applicable collaborator, supervisor and institutional publication conditions.
- [ ] Check third-party redistribution conditions.
- [ ] Agree on licensing and accurate author contributions before a formal source or data release.
- [ ] Use only verified author, affiliation, DOI, ORCID and repository information.

## Final package

- [ ] Check the actual file list and internal links.
- [ ] Keep synthetic tests, execution evidence and scientific validation distinct.
- [ ] Review the exact commit contents and any included history.
- [ ] Confirm authorization for the intended external publication.

Repository publication does not authorize deployment, cloud configuration changes or device operation.
